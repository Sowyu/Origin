# New tab machinery in Origin's main process

Date: 2026-10-13. Research only, read from source. No build, no run, no measurement. Nothing here is a memory or CPU number. Every claim has a file and line. "Unverified" marks a guess.

Paths starting with `engine/` are Firefox 157.0.1 source. Paths starting with `src/` and `prefs/` are Zen's and Origin's. `engine/browser/app/profile/zen.js` is the generated file the yaml prefs compile into.

## Short version

1. Zen almost never shows about:newtab or about:home. Cmd+T opens the urlbar over Zen's own about:blank tab.
2. Firefox still builds the whole Activity Stream (the newtab add-on) in the main process after the first window is restored. `browser.newtabpage.enabled` false does not stop that.
3. Zen's `feeds.topsites` false and `feeds.section.topstories` false are not feed switches. `feeds.topsites` only hides the Shortcuts section. The real switches are `feeds.<name>` prefs such as `feeds.weatherfeed`.
4. ASRouter starts on idle at every launch and loads four message providers. Zen's CFR user prefs do not turn the CFR provider off.

## 1. Does Zen show about:newtab or about:home?

### New tab (Cmd+T, the plus button)

- Zen's empty tab is a normal tab on `about:blank` with the attribute `zen-empty-tab`. It is created in `src/zen/spaces/ZenSpaceManager.mjs:236-253`.
- The attribute is set in a Tabbrowser patch, `src/browser/components/tabbrowser/Tabbrowser-sys-mjs.patch:346-348`.
- `zen.urlbar.replace-newtab` is true (`prefs/zen/zen-urlbar.yaml:5-6`). With it true, a new tab command with `where === "tab"` and no URL opens the floating urlbar and returns, so no about:newtab loads. See `src/zen/common/modules/ZenUIManager.mjs:545-552`. The getter is at `src/zen/common/modules/ZenUIManager.mjs:1841-1846`.
- If the conditions at `ZenUIManager.mjs:545-549` fail (a URL was passed, clipboard search, or `where` is not "tab"), the code falls through to Firefox's normal path. That loads `AboutNewTab.newTabURL`, which is `about:newtab` (`engine/browser/modules/AboutNewTab.sys.mjs:42,132`, and `engine/browser/base/content/utilityOverlay.js:73`). Which UI actions reach this path is unverified.
- A private window's new tab is `about:privatebrowsing`, not about:newtab (`engine/browser/base/content/utilityOverlay.js:41-50`). It is a separate page. Whether it needs any Activity Stream feed is unverified.

### Startup and new windows

- `prefs/firefox/browser.yaml:5-6` sets `browser.startup.page` to 3 (resume session). Nobody sets `browser.startup.homepage` in `prefs/`, so it keeps Firefox's default `about:home` (`engine/browser/app/profile/firefox.js:338`).
- With page 3, Firefox treats the homepage as a startup page: `getNewWindowArgs` returns `HomePage.get()` for choices 1 and 3 (`engine/browser/components/BrowserContentHandler.sys.mjs:806-812`).
- At startup, `uriToLoadPromise` drops the homepage if session restore will override it (`engine/browser/base/content/browser-init.js:1085-1096`). So a normal launch with a saved session does not load about:home.
- A first launch with no session, and a new window (`getNewWindowArgs`), do load `about:home` into the initial tab (`BrowserContentHandler.sys.mjs:806-812,835-841` and `browser-init.js:945-948`).
- Zen then removes that tab. `handleInitialTab` marks the initial tab for replacement when its remote type is empty or privileged-about (`src/browser/components/tabbrowser/Tabbrowser-sys-mjs.patch:110`). `ZenSpaceManager.mjs:884-892` keeps the tab only if the startup URL is not an initial page. `isInitialPage` lists about:home, about:newtab and about:blank (`engine/browser/base/content/browser.js:758-769`). The removal at `ZenSpaceManager.mjs:941-950` runs after the load was requested. Whether the page really starts loading (and starts the privileged about process) before removal is unverified.
- `ZenSpaceManager.selectEmptyTab` falls back to the first URL in `browser.startup.homepage` when the empty tab is gone or replace-newtab is false (`ZenSpaceManager.mjs:199-226`). That is about:home today.
- The Home button loads `HomePage.get()`, which is about:home (`engine/browser/base/content/browser-commands.js:152-176`). Whether Zen shows a Home button is unverified.
- Session restore can add a new-tab page at `engine/browser/components/sessionstore/SessionStore.sys.mjs:7891`. When that runs under Zen is unverified.

### Answer

A new window shows Zen's empty tab with the urlbar open, after a brief about:home load that Zen removes (unverified at runtime). about:newtab and about:home stay reachable through the fall-through paths above.

## 2. What starts in the parent process

### Order of events

1. `AboutNewTab.init` runs on the `browser-first-window-ready` category (`engine/browser/components/BrowserComponents.manifest:158`). It registers the newtab resource mapping, turns Activity Stream "on" and sets the TOU observer (`engine/browser/modules/AboutNewTab.sys.mjs:40-95`). Nothing heavy happens yet.
2. `TelemetryReportingPolicy` runs `_delayedSetup` on `sessionstore-windows-restored` and sends `telemetry-tou-accepted-or-ineligible` (`engine/toolkit/components/telemetry/app/TelemetryReportingPolicy.sys.mjs:1123-1124,1155-1165`). Origin sets `termsofuse.bypassNotification` true (`prefs/privatefox/disablemozilla.yaml:35-36`), so this fires at startup.
3. `AboutNewTab.observe` receives that and dispatches `onBrowserReady` (`AboutNewTab.sys.mjs:349-361`). `onBrowserReady` waits for the built-in add-on, the Nimbus `newtabTrainhop` feature and the profile age. Then it runs `new ActivityStream(...)` and `activityStream.init()` (`AboutNewTab.sys.mjs:187-248`). This happens whether or not any newtab page is ever opened.
4. `ActivityStream.init` sets default prefs, registers actors and calls `store.init(feeds, ...)` (`engine/browser/extensions/newtab/lib/ActivityStream.sys.mjs:2626-2651`). `Store.init` creates every feed whose `feeds.<name>` pref is true, telemetry first (`engine/browser/extensions/newtab/lib/Store.sys.mjs:116-130`). Each feed then gets the INIT action.
5. In parallel, the idle task `ASRouterNewTabHook.createInstance` starts ASRouter (`engine/browser/components/BrowserGlue.sys.mjs:1229-1234`). It is in `lateTasks`, so it runs on idle after first paint. There is no pref gate on that task.

### Other things that start from the newtab component

- `AboutNewTabResourceMapping.init` maps `resource://newtab`, reads the built-in add-on version and adds an add-on install listener (`engine/browser/components/newtab/AboutNewTabResourceMapping.sys.mjs:181-200,253-262`). Startup, cheap.
- It also schedules the train-hop add-on update (`AboutNewTabResourceMapping.sys.mjs:722-741`, called from `AboutNewTab.sys.mjs:223`). The train-hop update is driven by Nimbus. Origin sets `nimbus.rollouts.enabled` false (`prefs/origin/background.yaml:10`). What that does to the train-hop path is unverified.
- `NewTabPagePreloading.maybeCreatePreloadedBrowser` runs at window delayed startup (`engine/browser/base/content/browser-init.js:1038`) and on tab events (`engine/browser/components/tabbrowser/content/tabs.js:1659`). Origin's `browser.newtab.preload` false (`prefs/origin/memory.yaml`, last entry) makes `enabled` false (`engine/browser/components/tabbrowser/NewTabPagePreloading.sys.mjs:32-38,190-200`). Done.
- `NewTabUtils.init` and `PageThumbs.init` also run on `browser-first-window-ready` (`BrowserComponents.manifest:161-162`). What they cost is unverified. TopSitesFeed registers a thumbnail expiration filter (`TopSitesFeed.sys.mjs:1028`), so PageThumbs is tied to it.
- `AboutHomeStartupCache` is not set up when `browser.startup.page` is not 1 (`engine/browser/components/newtab/AboutHomeStartupCache.sys.mjs:142-147`). Zen uses 3, so it is already off.

### ASRouter

- `ASRouter.init` initializes ASRouterPreferences, ToolbarBadgeHub and MomentsPageHub, loads local providers, reads the IndexedDB storage, updates providers and loads messages (`engine/browser/components/asrouter/modules/ASRouter.sys.mjs:1202-1294`).
- Default providers are `message-groups` (Remote Settings), `onboarding` (local), `cfr` (Remote Settings) and `messaging-experiments` (Nimbus) (`engine/browser/app/profile/firefox.js:2041-2044`).
- `_updateMessageProviders` keeps a provider only if its JSON says `enabled` and `getUserPreference(p.id) !== false` (`ASRouter.sys.mjs:867-880`). `getUserPreference` maps only the keys `cfrAddons` and `cfrFeatures` to prefs (`engine/browser/components/asrouter/modules/ASRouterPreferences.sys.mjs:262-265`, and the table at `:37-41`). A provider with id `cfr` reads a pref literally named `cfr`, which does not exist, so it returns true.
- So Zen's `asrouter.userprefs.cfr.addons` and `.features` false (`prefs/privatefox/disablemozilla.yaml:18-23`) do not remove the `cfr` provider. They only filter CFR messages by category (the category filter code was not read, unverified). The Remote Settings fetch for `cfr` and `message-groups` still runs at startup (`ASRouter.sys.mjs:339-350,413-414,1026-1046`).
- The local `onboarding` provider builds its message list in the main process (`ASRouter.sys.mjs:885-892`).
- ASRouter has no timer of its own. It reloads on pref changes, locale changes, Nimbus updates and trigger messages (`ASRouter.sys.mjs:858,1178,2540-2550,2767`). The `updateCycleInMs` value only matters when one of those reloads runs.
- Other users of ASRouter: the default browser check waits for `ASRouter.waitForInitialized` and sends a trigger (`BrowserGlue.sys.mjs:1810-1819`), and Telemetry's TOU flow can ask it for a message (`TelemetryReportingPolicy.sys.mjs:1190-1195`).

All are true by default except `section.highlights` and `sportsfeed`. Defaults are only written when no default exists yet (`engine/browser/extensions/newtab/lib/ActivityStreamPrefs.sys.mjs:72-82`), so a pref in `zen.js` wins.

### Zen's current newtab prefs

- `feeds.topsites` false hides the Shortcuts section. It is a display pref (`PrefsFeed.sys.mjs:53`, `TopSitesFeed.sys.mjs:62`, `ActivityStream.sys.mjs:465`). The feed itself is `feeds.system.topsites`, which stays true.
- `feeds.section.topstories` false makes `showStories` false (`DiscoveryStreamFeed.sys.mjs:286-293`). That is a real saving: no story or spoc fetch.
- `browser.topsites.contile.enabled` false (`prefs/firefox/newtab.yaml:11-12`) stops the sponsored tile fetch. I did not read the Contile code that checks it. Unverified.
- `system.showWeather` false stops weather (see the table).
- Wallpapers true (`prefs/firefox/newtab.yaml:17-21`) costs a Remote Settings client and fetch at every launch for a page Origin does not show. I found no use of the pref in `src/` (grep of `src/` outside tests).

## 3. Which prefs stop each part, and what breaks

### What `browser.newtabpage.enabled` false really does

- about:newtab loads `chrome://browser/content/blanktab.html` instead of the Activity Stream page (`engine/browser/components/newtab/AboutNewTabRedirector.sys.mjs:36-40,543-548,616-621,462-464`).
- about:home is not affected. `newChannel` always sends `about:home*` to the Activity Stream page (`AboutNewTabRedirector.sys.mjs:543-548`).
- It turns preloading off (`NewTabPagePreloading.sys.mjs:32-38`).
- It disables the reload button on about:newtab (`engine/browser/base/content/browser.js:2290`) and removes about:newtab from the ASRouter callout check (`ASRouterTriggerListeners.sys.mjs:2003,2037`).
- It does not stop `AboutNewTab.init`, `onBrowserReady`, `new ActivityStream` or any feed. I found no check of the pref in those paths (reads of the pref were listed with grep in `engine/browser/components`, `modules` and `base`; only the files above and the preferences UI read it).
- Breaks: the Home panel dropdown in about:preferences (hidden by Zen anyway), and any code that expects about:newtab to be the Activity Stream page.

### How to stop Activity Stream itself

- No single pref prevents `new ActivityStream(...)`. The class always constructs and runs `init`.
- Each feed has its own pref (table above). Setting it false stops `Store.init` and `Store.onPrefChanged` from creating the feed (`Store.sys.mjs:91-130`).
- `browser.newtabpage.activity-stream.testing.shouldInitializeFeeds` false would start only `feeds.system.topsites` and `feeds.prefs` (`ActivityStream.sys.mjs:238-247,2611-2623`). It is a test pref. It would also drop `places` and `systemtick`, which the top sites feed needs to stay current, so I do not recommend it.
- `AboutNewTab.newTabURL` set by an extension makes `activityStreamEnabled` false, but `onBrowserReady` still runs (`AboutNewTab.sys.mjs:97-133,187-248`). Not useful.

### The Zen urlbar uses the top sites feed

- Zen locks `browser.urlbar.suggest.topsites` true (`prefs/firefox/urlbar.yaml:56-58`).
- `UrlbarProviderTopSites` shows top sites only if that pref and `feeds.system.topsites` are both true (`engine/browser/components/urlbar/UrlbarProviderTopSites.sys.mjs:37-40,113-126`). It reads the list from `AboutNewTab.getTopSites()` when `browser.topsites.component.enabled` is false (`UrlbarProviderTopSites.sys.mjs:121-125`). That pref is false in Firefox 157 (`engine/browser/app/profile/firefox.js:1926`).
- So `feeds.system.topsites`, `places`, `favicon` and `prefs` must stay on while Origin keeps the empty-urlbar top sites list.
- Option to look at later: set `browser.topsites.component.enabled` true. Then the urlbar calls `TopSites.getSites()` from `engine/browser/components/topsites/TopSites.sys.mjs`, which starts on first use. That would let every feed go off. I have not read that component beyond its imports (`TopSites.sys.mjs:1-60`). Unverified, and it is a newer code path.

## 4. Other parent-process startup work Origin does not use

Items below start at first window or idle through `BrowserComponents.manifest` categories or `BrowserGlue` tasks. Only items I could show are listed.

### Starts without being used

- Profile datastore. `ProfilesDatastoreService.init` runs on `browser-first-window-ready` (`BrowserComponents.manifest:165`). Its `#init` opens a SQLite connection and creates tables, with no pref check (`engine/toolkit/profile/ProfilesDatastoreService.sys.mjs:452-480,525-537`). Zen already sets `browser.profiles.enabled` false (`prefs/firefox/browser.yaml:53-54`), and `SelectableProfileService.init` returns early when disabled (`engine/browser/components/profiles/SelectableProfileService.sys.mjs:565-579`). The datastore still opens: Zen's own template profile contains `caf88a26.sqlite` matching `toolkit.profiles.storeID` (`/Users/mrm/Zen-Origin-research/perf.noindex/templates/zen-1.23.2b/split/prefs.js:179`). No pref stops it. A patch that removes the manifest line is the only way (one line, but check what else reads `storeID` first, unverified).
- IP Protection. `IPProtectionActivator.init` runs on `browser-first-window-ready` (`BrowserComponents.manifest:169`). `IPProtectionService.init` returns at once when `browser.ipProtection.enabled` is false (`engine/toolkit/components/ipprotection/IPProtectionService.sys.mjs:94-100`, pref default at `firefox.js:3696`). The module graph still loads: `IPProtectionHelpers.sys.mjs` imports six modules statically (`engine/browser/components/ipprotection/IPProtectionHelpers.sys.mjs:11-17,20-30`). No pref avoids the import. Memory cost unverified.
- Content relevancy. `ContentRelevancyManager.init` runs on idle (`BrowserComponents.manifest:189`). It creates a Rust store manager and a Nimbus listener even though the feature is off (`engine/toolkit/components/contentrelevancy/ContentRelevancyManager.sys.mjs:88-107`, default off at `firefox.js:3683`). No pref avoids the init.
- GenAI. `GenAI.init` runs on idle (`BrowserComponents.manifest:185`). It reads chat prefs and reorders providers (`engine/browser/components/genai/GenAI.sys.mjs:280-298`). Origin already turns the chat features off (`prefs/firefox/ai.yaml`, `prefs/origin/ai.yaml:21`). The init itself has no pref.
- Quick Suggest. Locked off by Zen (`prefs/firefox/urlbar.yaml:35-45`). `QuickSuggest.init` is still on the idle list (`BrowserComponents.manifest:186`). What it does when disabled was not read. Unverified.

### Already off or not worth a change

- Firefox View. `FirefoxViewHandler.init` only adds a CustomizableUI listener and a lazy getter (`engine/browser/base/content/browser.js:5105-5114`). Nothing heavy at startup.
- Sidebar revamp. Zen locks it false (`prefs/firefox/browser.yaml:32-34`).
- Default browser agent. `DefaultAgentScheduler` is under `#ifdef MOZ_DEFAULT_BROWSER_AGENT` (`BrowserComponents.manifest:201-203`). I did not check whether the macOS build defines it. Unverified.
- Screenshots. `ScreenshotsUtils.monitorScreenshotsPref` runs as a late idle task (`BrowserGlue.sys.mjs:1150-1154`) and initializes only if the screenshots pref is on (`engine/browser/components/screenshots/ScreenshotsUtils.sys.mjs:234-242`). Zen patches the screenshots overlay CSS (`src/browser/components/screenshots/overlay/overlay-css.patch`), so it keeps the feature. Leave it.
- Aboutwelcome. Zen sets `browser.aboutwelcome.enabled` false (`prefs/privatefox/disablemozilla.yaml:28-29`). The idle task `AWToolbarButton.SetupButton` still runs, but I did not read what it does when the feature is off (`BrowserGlue.sys.mjs:1215-1226`). Unverified.
- Captive portal check. Already off (`prefs/origin/background.yaml:19-20`).
