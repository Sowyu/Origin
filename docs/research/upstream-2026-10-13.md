# Upstream check, 2026-10-13

Question: has Zen or Firefox shipped anything since Origin's base (Zen 1.23.2b on Firefox 157.0.1) that Origin should take now? I read the GitHub REST API (public, no token), product-details.mozilla.org and mozilla.org/security/advisories. I fetched nothing into this repo and ran no build, app or `scripts/sync-upstream`. Patch overlap numbers come from raw files on raw.githubusercontent.com.

The highs include many sandbox escapes and use-after-free bugs in WebGPU, Canvas2D, WebAssembly, DOM Core, Graphics and Content Processes (for example CVE-2026-100758, CVE-2026-100760, CVE-2026-100762, CVE-2026-100781). Only one entry names a platform, a downloads spoof on Android. The rest are platform-neutral, so I treat them as affecting macOS.

Origin is on 157.0.1, so it already has every fix above. The next advisory will be for 158 and does not exist yet. I cannot say what is in it.

## Does Origin need to rebase now for security

No. Origin's Firefox base (157.0.1) is the newest stable release and carries MFSA 2026-97 and 2026-104. A rebase today would not add a security fix. It would move Origin to Zen's Firefox 158.0 commit while 158.0 is not yet released, so Origin would ship an unreleased Firefox with no published advisory. That cuts against the rule to keep Firefox's security fixes in step.

## Zen on Firefox 158

Yes, on `dev` only. `bfae69ff` (2026-10-11 12:41 UTC, "gh-15893: Update to Firefox `158.0`", https://github.com/zen-browser/desktop/commit/bfae69ff) changes 131 files in the GitHub commit listing, 23 of them patches. The rehearsal counted 144 for the whole move from 1.23.2b to `bfae69f`, which includes the commits before it. Zen's `surfer.json` on `dev` keeps `version` at 157.0.1 and sets `candidate` to 158.0. It is not tagged, not on `stable` and not released. `scripts/sync-upstream` fetches only stable tags, so it will not pick it up by itself. It would only do so through `--tag` with a tag that exists.

The earlier note `docs/research/rebase-rehearsal-2026-10-13.md` already replayed Origin onto `bfae69f` and onto `42d5c34`. It found 31 clean commits, 1 auto-resolved and 3 conflicting before the script changes, and 8 files that still need a person after them (7 in the "Cut Zen features" commit plus `ZenUIManager.mjs` again). I did not repeat it.

### Overlap between Origin's patches and what changed

Method: Origin keeps 191 patch files under `src/` outside `external-patches`. For each I took the Firefox file named on its first `diff --git` line and compared its raw content at `FIREFOX_157_0_1_RELEASE` and `FIREFOX_158_0_BUILD2`. A file that returns 404 at both tags would count as "same", so the unchanged count could be a little high. Files that changed show as changed, including renames such as `tabs.js` to `tabs.mjs`.

- 91 of 191 Origin patches sit on a Firefox file that changed between 157.0.1 and 158.0 build 2. That is the Firefox side of Zen's work, and Zen redoes it in its own patches.
- Origin edited 25 patch files itself (the others it carries as Zen ships them, or deleted: 70 patch files deleted, 3 added). Of those 25, 11 sit on a changed Firefox file: `browser-xhtml`, `navigator-toolbox-inc-xhtml`, `nsContextMenu-sys-mjs`, `BrowserComponents-manifest`, `preferences-js`, `preferences-xhtml`, `SessionStore-sys-mjs`, `Tabbrowser-sys-mjs`, `tab-js`, `tabs-js` and `toolkit/moz-configure`.
- Zen's `bfae69ff` itself rewrites 23 patch files. 4 of them are patches Origin also edited: `BrowserContentHandler`, `SessionStore`, `Tabbrowser` and `tabs-js` (renamed to `tabs-mjs`). The compare against 1.23.2b lists 22 changed patches, and 5 of them are Origin-edited (those 4 plus `preferences-js`).
- None of the 70 patches Origin deleted is changed by Zen in this window.

So the real conflict surface is about 5 patch files plus the JS and CSS under `src/zen/` (`ZenCompactMode.mjs`, `ZenUIManager.mjs`, `ZenSpaceManager.mjs`, the animation CSS). That matches the rehearsal.

## What the 157 to 158 move costs

The rehearsal put it at 8 files for a person after the script fixes, plus one rename (`tabs-js.patch` to `tabs-mjs.patch`) that the script does not handle. I have not rebuilt or measured Origin on 158, so build and performance cost is unknown. Origin's own diff against `upstream` is 576 files, so a rebase touches a large surface even with few conflicts.

## Recommendation

Wait for the next Zen tag, which should carry Firefox 158.0 once Mozilla releases it. Do not rebase onto `dev` now.

1. Origin is already current on Firefox security, so waiting costs nothing in safety.
2. `dev` is untagged and sits on a Firefox that has no `RELEASE` tag or advisory yet.
3. A tag lets `scripts/sync-upstream` run as designed.

Triggers to act: a Zen tag appears with Firefox 158.0 (check `curl -s https://api.github.com/repos/zen-browser/desktop/releases/latest`), or Mozilla publishes a high-impact advisory that fixes a bug in a component that Origin ships and 157.0.1 lacks. In either case, run `scripts/sync-upstream --dry-run` first, after the measurement batch ends.

Unverified: Mozilla's 158.0 release date, any advisory for 158, and whether Zen's next tag takes `dev` as it stands today.
